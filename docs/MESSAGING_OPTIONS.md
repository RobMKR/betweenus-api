# Messaging options for BetweenUs

Reviewed November 21, 2026.

Start with a Telegram bot in one existing friends’ group. Keep Supabase email sign-in and verification. Evaluate WhatsApp as an opt-in channel for one-to-one app notifications once Meta confirms that the intended use and templates are allowed.

## WhatsApp notifications

- The Meta Cloud API sends from a registered business number. Set up a Meta app, business portfolio, WhatsApp Business Account, business phone number, server-side credentials, billing, and delivery webhooks. The Expo app can show preferences and link a verified number to the user’s existing account. Keep the sender credentials in the Fastify backend. [Cloud API onboarding](https://developers.facebook.com/documentation/business-messaging/whatsapp/get-started/), [Business number registration](https://developers.facebook.com/docs/graph-api/reference/whats-app-business-account-to-number-current-status/register/)
- Collect the recipient’s number and affirmative opt-in for the types of notifications they will receive, and honor opt-outs. A friend supplying someone else’s number does not provide that recipient’s consent. Business-initiated messages require approved templates. A user message opens a 24-hour customer service window in which ordinary replies are possible. Outside the window, approved templates are required. [WhatsApp Business Messaging Policy](https://business.whatsapp.com/policy)
- Meta’s policy restricts peer-to-peer lending and debt collection. Confirm with Meta how it classifies BetweenUs’ friends-and-family loans, shared-expense reimbursements, and the proposed notification text before building or shipping debt-related WhatsApp notifications. An approved category alone does not establish that the use case complies. [WhatsApp Business Messaging Policy, section 4](https://business.whatsapp.com/policy)
- Meta bills per delivered message by category and recipient market. Since October 1, 2026, utility templates can incur charges inside as well as outside the 24-hour window. Each business phone number gets 1,000 free delivered service replies per month and pays for subsequent service replies. The service allowance does not cover proactive utility templates. Estimate spend by multiplying the number of delivered notifications in each recipient market by its current utility rate, then add any provider fees. [Meta developer pricing and rate cards](https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing/)
- WhatsApp’s Groups API requires an Official Business Account and a compatible Cloud API number. Meta documents creating an invite-only group for up to eight participants. It provides no documented path to attach a bot to an existing personal group. [Groups API](https://developers.facebook.com/documentation/business-messaging/whatsapp/groups/), [Get started](https://developers.facebook.com/documentation/business-messaging/whatsapp/groups/get-started), [Official Business Accounts](https://developers.facebook.com/documentation/business-messaging/whatsapp/official-business-accounts)
- WhatsApp-delivered OTP sign-in is a separate feature. Supabase currently supports the WhatsApp OTP channel through Twilio or Twilio Verify. For the pilot, use email for authentication and verify any WhatsApp notification destination while the user is signed in. [Supabase phone sign-in](https://supabase.com/docs/guides/auth/phone-login)

## Telegram bot in an existing group

1. Have an authorized group member add the bot and a BetweenUs group owner approve the chat-to-group binding in the app. Keep Telegram privacy mode on and leave the bot as a regular group member. Use a directed command such as `/paid@BetweenUsBot`, or write the same sentence as a reply to the bot’s prompt while keeping privacy mode on. Ordinary group messages do not reach a privacy-mode bot. Passive recognition of those messages requires administrator status or privacy mode disabled, with re-addition after changing that setting. [Telegram group privacy mode](https://core.telegram.org/bots/features#privacy-mode)
2. From a signed-in BetweenUs session, generate a short-lived, one-use link with a signed nonce or an opaque token backed by server state. The user opens the bot’s private `/start` link, then confirms the link in the signed-in app. Store Telegram’s stable numeric user ID against that BetweenUs account and support revocation. Require linked active group membership for each action and restrict private follow-ups to users who have opened a bot conversation. [Telegram deep links](https://core.telegram.org/bots/features#deep-linking), [Telegram bots](https://core.telegram.org/bots), [Telegram user IDs](https://core.telegram.org/bots/api#user)
3. Route Telegram updates to a Fastify HTTPS webhook. Verify the Telegram secret header, deduplicate update IDs, and bind every confirmation to its intended actor and expiring proposal. In Postgres, recheck authorization and the current balance in the same transaction that records the repayment. Use the same repayment service from the app and bot, and a transactional outbox for notifications after commit. Bot commands can only match data already synced to the server. [Telegram webhook](https://core.telegram.org/bots/api#setwebhook), [Telegram update IDs](https://core.telegram.org/bots/api#update)
4. Telegram’s default Bot API message allowance has no per-message charge. Its published guidance is about one send per second per chat, up to 20 sends per minute in a group, and about 30 sends per second for bulk traffic before paid broadcasts. Hosting and any model calls still cost money. [Telegram bot limits](https://core.telegram.org/bots/faq#broadcasting-to-users)

### Example

A linked payer sends `/paid@BetweenUsBot I paid 45 to Sergey for 20 Nov football`. The bot extracts amount `45`, payee `Sergey`, day and month `20 Nov`, and event hint `football`. The backend looks up the payer’s open obligations in that bound group, matches the payee and event, and resolves dates using the group’s time zone. The current year and currency can come from the unique matching record. Where there is ambiguity about the person, date, year, currency, or debt, ask the payer to choose in a private conversation or the app. A missing record can be retried after sync.

If one exact obligation matches, show the payer a preview such as **Record AED 45.00 paid to Sergey for Football on 20 Nov 2026?** After the payer confirms, record the report as pending Sergey’s acknowledgement. Apply it to the balance after Sergey accepts through his own linked account. Mark the obligation settled only when its accepted repayments cover the full balance. Keep the event, amount, currency, participants, and action history available for review. This records a reported transfer that occurred outside BetweenUs.

## Implementation order

1. Extend the Fastify/Postgres ledger with events or an equivalent event reference, repayment reporting and acknowledgement, and idempotent balance updates. The current API supports debt acceptance and principal balances. See [API README](../README.md) and [pilot roadmap](PILOT.md).
2. Pilot an explicit Telegram command with a deterministic parser in one existing group. Use linked accounts, a private preview, payer confirmation, payee acknowledgement, and in-app visibility of pending and accepted repayments.
3. Add a small model only if deterministic parsing misses common phrasings. Send the submitted command text, minimize identifiers, and require structured extraction of intent, amount, currency hint, payee hint, and event date/title hints. Keep matching, authorization, confirmation, and writes in the backend. Measure accuracy on representative inputs before picking a provider or estimating model cost.
4. If Meta confirms the WhatsApp use case, add it as a one-to-one delivery option behind the same outbox. Submit representative templates, verify phone destinations and consent, and test actual delivery costs for pilot recipient markets.
